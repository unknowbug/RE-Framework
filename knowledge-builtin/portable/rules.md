# Portable Knowledge — 提炼规则（人工维护）

> **性质**：从 `knowledge-builtin/portable/` 的 273 条实战条目中提炼的**检查项/反模式清单**，不是规范条款。
> **证据等级**：每条规则后引用来源条目 key（`卷#条目`）；条目本身多为 `candidate`、部分 `confirmed`——规则继承其证据等级，**不因被写进本文件而升格**。
> **晋升路径**：规则 → 规范条款（spec）需人类确认 + 反复跨域验证；`candidate` 条目永不直接进入 spec。
> **用法**：Phase 0 预登记判据、Phase 2.5 验证、Phase 3 judge 审查时逐条对照；命中时回读原条目（`index.yaml` 定位）。

## A. 验证与判据（01）

1. 对拍中间层时，对拍物必须是**解析产物树 dump**，不是输入原文——原文对拍只证输入长什么样，证不了中间层把它变成了什么。[`01#12`]
2. 预登记判据必须写死**读法**（取哪列/哪档/边界归属），否则事后解释可任意漂移。[`01#112`]
3. 等价性证据按形态阶梯取强：整文件 sha256 > 条目级 sha/多重集 > 行数/计数；能用强形态就不用弱形态。[`01#142`]
4. 门禁自身要用**注入式负向测试**自证（改坏输入必须变红）；门绿只证明能跑，不证明能拦。[`01#172`, `02#27`]
5. `0 == 0` 的恒等对照不构成正例覆盖；必须证明判别路径真的被执行。[`01#177`]
6. 判据的覆盖面假设失效时，按预登记程序声明 VOID/降级；不得把"没测到"写成"不存在"。[`01#211`, `02#133`]
7. 跨 run 比较先做**同配置 run-to-run 噪声基线**；信号与噪声同阶时只能声称"无回归"，不能声称改进。[`01#51`, `01#92`]
8. 口径换代后旧基线必须**同口径复算**；新旧口径映射非单调，禁止按比例折算。[`01#127`, `01#128`]
9. 门控只判"存在/数量"是 silently-green 门；必须判语义或行为。[`02#163`]
10. 先修再发版：修后必须在噪声带内 ≡ 修前，且"臂变量生效"要自证。[`01#121`, `01#139`]

## B. 归因与调试（02）

11. 先证明工具/探针/自变量没错，再怀疑被测对象；探针输出先做 sanity check（坐标 bug 可造 100% 假象）。[`02#13`, `02#16`]
12. 残差先做**阶段分解**再定位机制；跨阶段混合残差直接归到单一层会误判。[`02#10`]
13. 打印坐标 ≠ 采样坐标；跨探针对比必须钉死坐标。[`01#17`]
14. "死参数"会制造假判别：必须行为化验证自变量真的被改变。[`01#20`, `02#37`]
15. 静态机制断言未实测不得当公理续推；一轮 dump 即可证伪。[`02#42`]
16. 判读源码语义前核对 **env 默认值方向 + 门控三查**（默认值/覆盖/生效证据）。[`02#38`, `02#53`]
17. 排除法结论必须列出"未测候选"边界，不得把未排除写成已排除。[`02#133`]
18. VOID/GATE 裁决必须**非零退出断链**，不能只发消息继续。[`02#160`]
19. 一次性诊断产物放唯一隔离区；破坏性采集台要考虑二次层证据不可回补。[`02#9`, `01#198`]
20. judge 独立复算不要复用同一变换代码（会复现同一 bug）；judge 建议也要廉价预检。[`01#41`, `08#60`]

## C. 工具链与环境（03）

21. 构建工具/守护进程会吞掉客户端 env：先核 daemon 复用与 env 继承，再信参数。[`03#32`, `03#2`]
22. 缓存/时间戳/UP-TO-DATE 不等于本次执行体生成：用内容指纹/执行签名判别，不用 mtime 或"在盘"。[`03#18`, `03#27`, `03#6`]
23. 裁剪历史命令参数会裁掉必带项；复用 run 时照抄完整参数清单。[`03#15`]
24. 写入型工具"解析+重建"会丢注释/格式；改配置前确认工具是否 round-trip。[`03#50`]
25. 目录级 ignore/untrack 会吃掉住在其内的门禁资产/源码；`!` 白名单在排除目录内无效。[`03#24`, `03#155`]
26. 跨平台路径/编码坑：`Join-Path` 不用字面反斜杠；git autocrlf 可造全量伪差异；程序化改 ps1 后跑 Parser 验语法。[`03#60`, `03#147`]
27. PowerShell 语义坑：`-like` 的 `[...]` 是字符集；`Select-Object -First` 会早退杀上游；逗号串被当单字符串。[`03#45`, `03#41`, `03#49`]

## D. 语言与编译器（04）

28. 复刻整数语义必须核位宽/符号/溢出：MSVC `long` 是 32 位、Java long 用 `wrapping_*`、无符号 parse 会静默 clamp。[`04#4`, `04#18`, `04#14`]
29. JSON/动态类型读取要核"类型形态枚举"：布尔走数值接口恒 false、非法形态静默腐蚀。[`04#8`, `04#16`]
30. 文档口径可能先于源码失准；以文档为依据前核一手源码（`static final` 非编译期常量）。[`04#13`, `04#26`]

## E. 性能与并发（05）

31. 跨 session 基准数字不可直接续推；微测样本模式决定缓存命中率，外推可差 40×。[`05#18`, `05#21`]
32. 多臂 bench 必须 chunk 粒度交错；性能 bench 必须串行，避免互相污染。[`05#24`, `05#28`]
33. 性能分母分场景（延迟 vs 吞吐可差一个数量级）；峰值内存 ≠ 存活集。[`05#83`, `05#119`]
34. 并发度 = 调用方池宽，引擎线程参数可能是死参数；先量后改。[`05#122`, `05#124`]

## F. GPU 编程（06）

35. FP32 精度要分离"大数整体精度"与"小数精度"；结构放大系数决定 float 硬上限。[`06#V1`, `06#V2`]
36. GPU 数据通道：带宽死局先算"上传总量 ÷ PCIe 带宽"；越界读 const 数组可能 TDR；dispatch 并发必须互斥。[`06#V19`, `06#V20`, `06#V21`]
37. GPU 验证先做"GPU 特有 vs 共同"二分；逐位对拍先分量后总值；单域验证是盲区制造机。[`06#V26`, `06#V24`, `06#V27`]

## G. 逆向与反编译（07）

38. 反编译/javap 输出不可直接信任；引用源码树/反编译参照前核版本/DataVersion。[`07#1`, `07#5`]

## H. 协作与流程（08）

39. judge 审查门是强制环节；收敛门 ≠ 自评；多疑点冲突先 fan-out。[`08#1`, `08#7`]
40. 交接物必须是确定性 dump/机械产出；交接条目转抄会漂移，接手第一动作 = git HEAD vs 交接文档交叉核对。[`08#86`, `08#90`, `08#193`]
